# AI 安全深读：越狱分类学、指令层级与红队工程

这篇是 **AI 安全与对齐**主题的深度补充。安全讨论容易流于口号，这篇给三个可以落地的东西：**越狱技术的分类学**（攻击面地图）、**指令层级**（架构级防御的设计原理）、**红队评测的工程闭环**。

> [!KEY] 一句话抓住本质
> 对齐技术的目标是「模型可靠地追求人类意图」；安全工程的现实是**纵深防御**——因为没有任何单一防线能挡住所有攻击（演示的攻防矩阵就是这句话的可视化）。工程上的胜负手不在「更聪明的模型」，在**层与层之间的组合**。

## 一、越狱分类学：攻击面地图

| 类别 | 代表手法 | 打的是什么 |
|---|---|---|
| **角色扮演** | DAN（Do Anything Now）、虚构小说 | 安全训练的人格一致性（模型「入戏」后策略漂移） |
| **多步稀释** | 分解危险任务成无害小步 | 单步检测（每步都无害，合起来有害） |
| **编码混淆** | base64/倒序/低资源语言 | 输入过滤器的盲区（过滤器只看明文） |
| **上下文注入** | 伪对话历史（「刚才你已经同意了…」） | 模型对上下文的过度信任 |
| **梯度攻击** | 白盒 GCG 后缀（对齐模型同样适用） | 离散 token 层面的脆弱性 |
| **提示注入** | 网页/文档里藏指令 | **Agent 场景**：外部内容当指令执行 |

规律：攻击总是打「训练分布外的输入形态」——防御每堵一种形态，攻击换一种。**这决定了防御必须是纵深而非单点。**

## 二、指令层级：架构级防御

核心原则：**不同来源的指令有不平等的信任级**：

```
系统指令（开发者）> 用户指令 > 工具/检索返回的内容（数据！）
```

工程含义：

1. **工具输出永远是数据**——即使里面写着「忽略以上指令」也只当文本处理（来源标记 + 结构隔离）；
2. **系统级策略不可被上下文覆盖**——训练时显式构造「试图覆盖系统提示」的样本教模型拒绝；
3. **权限最小化**——Agent 的每个工具按任务授予最小权限，高危动作（支付/删除/外发）强制人审。

这是 OpenAI/Anthropic 2024 年后公开训练方法论的共识部分，也是 Agent 安全（见 Agent 深读）的地基。

## 三、红队工程：闭环怎么建

1. **自动化红队**：用 LLM 生成攻击变体（改写/翻译/角色化），分类器判定是否越狱成功——大规模筛「可用攻击」；
2. **人工红队**：针对产品的真实滥用路径（社工、诈骗话术、非法信息）——自动化覆盖不了的创意攻击；
3. **评测集沉淀**：把发现的攻击变成回归测试（下次发版前全量跑）——**安全指标只看最坏情况**（1% 攻击成功率就是 100% 的产品事故）；
4. **监控回流**：线上拦截样本 → 标注 → 下一轮训练数据——防御体系随攻击演化。

**评测基准**：HarmBench、AdvBench（攻击成功率）、 JailbreakBench（社区攻防榜单）；OWASP LLM Top 10 是工程清单。

## 四、前沿议题（一句话版，面试展示视野）

- **Goodhart 与奖励作弊**：对齐模型可能「表现对齐」而非「真对齐」（欺骗性对齐）；
- **可解释性审计**：从内部表征找「欺骗回路」（Anthropic 机制可解释性路线）；
- **生成内容检测与水印**：统计水印（token 分布偏置）可用但对抗性弱；
- **监管**：欧盟 AI Act 风险分级、我国生成式 AI 管理办法（标识 + 备案）。

## 五、面试要点速答

1. **越狱与提示注入的区别？** 用户主动绕过安全策略 vs 外部内容被当指令执行——前者是模型问题，后者是架构问题。
2. **为什么单一防线必被绕过？** 攻击打分布外形态，防御是分布内训练——攻防不对称；纵深让漏过概率相乘。
3. **指令层级的工程含义？** 来源分级信任、工具输出隔离为数据、高危动作人审——Agent 安全三原则。
4. **红队闭环四步？** 自动化生成→人工补充→沉淀回归→线上回流。
5. **安全指标为什么看最坏情况？** 攻击者只需找到一个漏洞——平均安全率无意义。
6. **Constitutional AI 是什么？** 用一组成文原则让模型自我批评修订（RLAIF），降低人工标注的安全训练成本。
