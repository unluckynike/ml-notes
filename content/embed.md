# 多模态检索深读：双塔、交叉编码器与统一嵌入空间

这篇是**多模态检索与嵌入**主题的深度补充。上面标签页讲了「召回+重排」的分工，这篇回答三个更本质的问题：**双塔为什么快但糙（信息在哪一步丢的）**、**late-interaction 是怎么折中的**、**多模态统一空间是怎么「对齐」出来的**。

> [!KEY] 一句话抓住本质
> 检索的速度-精度权衡是一条连续谱：**双塔**（各自编码，余弦打分——文档可离线，快）→ **late-interaction**（文档多向量、token 级延迟交互——ColBERT）→ **交叉编码器**（拼接联合编码，逐 token 交互——最准）。生产管线 = 谱的左端召回、右端精排。

---

## 一、双塔丢掉了什么：交互信息的账

查询 q 与文档 d，双塔各自编码后算余弦：$\text{sim} = E_q(q)\cdot E_d(d)$。

问题：**「匹配证据」必须在向量内积里一次性表达**。查询「不宜空腹吃的药」，文档「阿司匹林空腹服用刺激胃」——真正的匹配信号是「不宜×空腹」「药×阿司匹林」这些 token 级对应关系；双塔把这些压缩进两个定长向量的内积，**细粒度对应在编码时就丢掉了**。

实证后果：双塔对「精确短语/否定/长尾实体」弱——这正是 BM25（字面精确）还能留在混合检索里的理由（见信息检索深读）。

## 二、ColBERT 的折中：延迟交互

$$\text{score}(q, d) = \sum_{i\in q}\max_{j\in d}\; \langle E_q(q_i), E_d(d_j)\rangle$$

文档**每个 token 各存一个向量**（离线算好），查询时对每个查询 token 找文档中最相似的 token（MaxSim）再求和——**交互发生在打分时而非编码时**，保住了 token 级对应关系，同时文档向量仍可离线预算（比交叉编码器快两个量级）。代价：存储膨胀（每文档几十上百个向量）——用 PQ 量化压。

## 三、多模态统一空间：对齐是怎么发生的

CLIP 式训练（对比损失拉近配对图文、推开非配对）之后，图与文落在同一个余弦空间。三件事值得知道：

1. **对齐的是「语义」不是「像素」**——「一张猫的照片」与猫图相邻，与「一张狗的照片」也只差一点点；细粒度（品种/数量）分不开（见 CLIP 深读的组合性短板）；
2. **「模态间隙」（modality gap）**：即便对齐，图嵌入与文嵌入仍各自聚成一团（锥形分布）——跨模态检索前常做中心化；
3. **ColPali（2024）的冲击**：文档检索不再「OCR→文本→嵌入」，直接把**页面截图切块嵌入**——版面、表格线、颜色这些「OCR 会丢的信息」全部保留，文档 RAG 的检索层正在被重写。

## 四、工程账本（与演示对照）

| 组件 | 延迟 | 存储 | 精度 |
|---|---|---|---|
| 双塔 + HNSW | ~ms 级 | 每文档 1 向量 | 召回好、排序糙 |
| ColBERT | ~10ms | 每文档 N 向量（压缩后） | 接近交叉编码器 |
| 交叉编码器 | ~100ms/对 | 无预存 | 最准（只排 top-50） |

**混合检索**（生产标配）：BM25（字面精确）+ 双塔（语义泛化）→ RRF 融合 → 交叉编码器重排——三层各司其职，缺一层就有一类查询翻车。

## 五、面试要点速答

1. **双塔 vs 交叉编码器的本质差别？** 交互时机：编码前 vs 打分时——前者可离线快，后者细粒度准。
2. **ColBERT 的 MaxSim 在算什么？** 每个查询 token 在文档所有 token 向量里的最佳匹配之和——late interaction 的延迟交互。
3. **模态间隙是什么、怎么处理？** 对齐后图文各自聚成窄簇；检索前中心化/归一化缓解。
4. **为什么多模态检索仍要混合 BM25？** 精确词命中与语义泛化是两种失败模式——单通道必漏一类。
5. **ColPali 改变了什么？** 文档检索从「OCR 后搜文本」变成「直接搜页面视觉 token」——版面信息零损失。
6. **重排为什么值得单独一层？** 交叉编码器每对都要前向（贵），但只对 top-50 跑——花小钱买排序质量的最大单项提升。
