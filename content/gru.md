# GRU 深读：做减法的艺术

这篇是 **GRU 门控循环单元**主题的深度补充。LSTM 深读里已对照过 GRU，这里专门回答：**砍掉一个门和细胞状态，为什么不掉点**——以及什么时候「少即是多」成立。

> [!KEY] 一句话抓住本质
> GRU 只保留两个门：**更新门 z**（一次决定「忘多少 = 写多少」，互补绑定）与**重置门 r**（决定候选记忆看多少过去）。它没有独立的细胞状态——隐藏态 h 自己承担记忆与输出。参数省 25%、更快，绝大多数任务与 LSTM 打平——「记忆容量」很少是瓶颈，**优化难度**才是。

---

## 一、公式与 LSTM 的逐行对照

$$z_t = \sigma(W_z[h_{t-1}, x_t])\quad\text{更新门：新信息写入多少（= 旧记忆保留 }1-z\text{）}$$

$$r_t = \sigma(W_r[h_{t-1}, x_t])\quad\text{重置门：算候选时看多少过去}$$

$$\tilde{h}_t = \tanh(W[r_t ⊙ h_{t-1}, x_t])\quad\text{候选记忆}$$

$$h_t = (1-z_t)⊙h_{t-1} + z_t⊙\tilde{h}_t$$

与 LSTM 的结构差（完整 LSTM 公式见其深读）：

| 组件 | LSTM | GRU |
|---|---|---|
| 门数 | 3（遗忘/输入/输出） | 2（更新/重置） |
| 状态 | c 与 h 分离（c 不限幅传递） | 只有 h（既当记忆又当输出） |
| 忘/写关系 | f 与 i 独立 | **硬互补**（1−z 与 z） |
| 参数 | 4h(h+x) | 3h(h+x) |

**梯度视角**：$\partial h_t/\partial h_{t-1}$ 的主导项是 $\text{diag}(1-z_t)$——与 LSTM 的 $\text{diag}(f_t)$ 同构，**加法+门控保梯度**的核心机制完整保留；砍掉的只是「输出门」这层细粒度遮罩。

---

## 二、互补绑定的得与失

「忘多少 = 写多少」（1−z 与 z 硬互补）是 GRU 最大的简化，也是它唯一的能力损失：LSTM 可以「既多忘又少写」（f 小 i 小，让 c 衰减）——**记忆总量收缩**；GRU 做不到（忘掉的量必须被新信息补上）。这个差异在需要「长期挂起大量无关状态」的任务（超长序列、大词汇语言模型）里偶尔显现，一般序列任务无感。

**实证共识**：GRU vs LSTM 的差距通常小于初始化/调参的波动——**选型先看工程**（显存、速度、下游生态），默认用「两者都跑一下取好」。

## 三、面试要点速答

1. **GRU 的两个门各管什么？** 更新门 z：新旧记忆的混合比（忘/写互补）；重置门 r：计算候选时对历史的取舍。
2. **相对 LSTM 砍了什么？** 输出门 + 独立细胞状态（c 与 h 合一）→ 参数 4h(h+x) 降为 3h(h+x)。
3. **GRU 怎么保梯度？** h 的加法更新主导项 diag(1−z)——同 LSTM 的遗忘门机制，无衰减通路。
4. **LSTM 还能做什么 GRU 做不了的？** 独立控制忘/写（记忆总量可收缩）与输出门遮罩——超长依赖/大容量任务偶有优势。
5. **实际怎么选？** 差距小于随机波动：小数据/省资源偏 GRU，超长序列偏 LSTM；都试最快。
6. **GRU 也解决不了什么？** 串行依赖导致的训练不可并行——这是注意力/SSM 阵营解决的层面。
