# CLIP 深读：对比目标、温度与零样本分类

这篇是 **CLIP 多模态**主题的深度补充。CLIP 用 4 亿「图-文对」训出两个编码器，从此「以文搜图」「零样本分类」成为标配，它也是当今所有 VLM 的视觉底座。这里讲清它的**训练目标（对比学习的 InfoNCE）**、**温度参数的微妙作用**和**真实的能力边界**。

> [!KEY] 一句话抓住本质
> CLIP 在一个 batch 里做「配对连连看」：N 张图和 N 句文本，正确的配对应该在相似度矩阵的对角线上。训练目标 = 按行按列做 softmax 交叉熵，**把对角线拉高、非对角线压低**——这正是 InfoNCE。学完后「图」和「文」被压进同一个余弦空间，任何标签都能写成一句话来检索。

---

## 一、训练目标：对角线上的分类

batch 内相似度矩阵 $S_{ij} = \langle I_i, T_j\rangle / \tau$（余弦相似度除温度 $\tau$）。对第 $i$ 行（图找文）：

$$L_i^{\text{I}\to\text{T}} = -\log\frac{e^{S_{ii}}}{\sum_{j=1}^{N}e^{S_{ij}}}$$

对列（文找图）同样一份，总损失 = 行 + 列平均。**每一行/列是一个 N 类分类**，「正确答案」是对角线元素——这就是对比学习把「配对」变成「分类」的技巧（InfoNCE 的一种形态）。

两个关键设计：

- **对称双向**：图→文与文→图同时训，两个塔都被约束（检索两个方向都好使）；
- **负样本来自 batch**：N=32768 的 batch 提供 3 万+ 负样本——**CLIP 的本质是用超大批量硬喂出来的**，这也是复现它最贵的地方。

---

## 二、温度 τ：一个被低估的参数

相似度除以 $\tau$（可学习，初始化 0.07）再过 softmax：

- $\tau$ 小 → 分布尖锐：梯度集中在**最难（相似）的负样本**上——「精耕细作」；
- $\tau$ 大 → 分布平缓：所有负样本雨露均沾——「广撒网」。

训练中 τ 会被自动压小（模型越来越挑硬负样本学）。这个参数对效果的影响常大于 backbone 换档——调对比学习先看温度。

---

## 三、零样本分类：把分类器写成一句话

ImageNet 分类不需要训练 1000 头：**把每个类名写成句子** "a photo of a {class}"，编码成 1000 个文本向量，图像向量与它们算余弦取最大——零训练的分类器。

$$\hat{y} = \argmax_{c}\;\langle I,\; T_c\rangle$$

两个涨点技巧：**prompt 工程**（"a satellite photo of a {class}" 对遥感图准确率大增）；**prompt ensemble**（80 个模板的文本向量取平均）。这些「写提示的功夫」就是后来提示工程在多模态的雏形。

## 四、能力边界（考官爱问）

| 局限 | 原因 |
|---|---|
| **组合性差** | 「方块上面的红球」这类空间/属性绑定常错——对比目标对 bag-of-words 式的全局匹配偏置，不做细粒度绑定（这是 VLM 用生成式对齐要解决的） |
| **细粒度/计数弱** | 4 亿图文对里很少出现「3 只鸟 vs 4 只鸟」的监督信号 |
| **非分布域崩** | 见过的图文分布外（医疗影像、特定领域）零样本性能骤降 |
| **只是检索不是理解** | CLIP 不生成、不推理；它是「对齐底座」，复杂推理要靠接 LLM（LLaVA 路线） |

> [!TIP] CLIP 的现代角色
> 视觉编码器（CLIP ViT）+ 投影层 + LLM = VLM 的标准配方；CLIP 还活在：检索/搜图、零样本审核、扩散模型的文本条件（SD 的文本塔）、RAG 的多模态编码。对比学习一脉后来发展出 SigLIP（sigmoid 损失换掉 softmax，无需超大批量）——思想未变，工程在进化。

## 五、面试要点速答

1. **CLIP 的损失是什么？** 对称的图→文 / 文→图 softmax 交叉熵（InfoNCE），正样本是 batch 内配对，负样本是其余 N−1 个。
2. **温度参数的作用？** 缩放相似度控制 softmax 尖锐度，间接决定「聚焦硬负样本」的程度；可学习且训练中自动变小。
3. **零样本分类怎么做？** 类名写成 prompt → 文本编码 → 与图像嵌入比余弦；prompt ensemble 提稳定性。
4. **为什么需要超大批量？** 负样本只来自同 batch，对比学习的效果随负样本数显著上升（SigLIP 用逐对 sigmoid 摆脱了这点）。
5. **CLIP 与 VLM 的关系？** CLIP 提供对齐的视觉/文本嵌入（检索式）；VLM 把视觉 token 拼进 LLM 上下文做生成式理解——前者是后者的常用底座。
6. **CLIP 空间的「各向异性」问题？** 未经约束的嵌入会挤在窄锥里，检索退化——对比损失本身 + 温度 + 均匀性正则缓解；实际使用前常再归一化。
