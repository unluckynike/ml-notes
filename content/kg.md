# 知识图谱深读：从构建管线到 GraphRAG

这篇是**知识图谱**主题的深度补充。上面标签页演示了多跳推理（图搜索），这篇讲落地最重的两块：**构建管线**（抽取/对齐/融合——成本大头）与**KG 与 LLM 的三种结合方式**（GraphRAG 只是其中之一）。

> [!KEY] 一句话抓住本质
> 知识图谱的全部价值与全部成本都在同一个地方：**把非结构化世界变成精确的结构**。构建贵（抽取/对齐/更新），但建成后换来「关系型问题的精确可解释回答」——LLM 时代的新分工：**图管事实与结构，LLM 管语言与推理**。

---

## 一、构建管线：四步与各自的坑

1. **实体抽取（NER）**：识别人/组织/地点/产品。坑：边界与粒度（「阿里巴巴集团」vs「阿里巴巴」）；LLM 时代用 prompt 抽取效果远超传统序列标注，成本反而不高了。
2. **关系抽取**：判断实体对的谓词（效力于/位于/持股）。坑：远程监督（用已有 KG 对齐语料自动打标）带来的噪声。
3. **实体对齐与消歧**：「姚明」是球员还是品牌？「IBM」=「国际商业机器」？——同名实体消歧、异名实体合并是**图谱质量的决定性环节**，也是最难自动化的。
4. **schema 设计**：定义有哪些实体类型与关系类型——过早定死限制扩展，过松导致图谱退化成「带标签的网」。**先粗后细、随数据演化**是务实路线。

维护成本常被低估：现实世界在变（高管变动、公司改名）——没有更新管线的 KG 一年内就开始「说谎」。

---

## 二、KG 嵌入：把关系变成向量运算

TransE（2013）的经典假设：**关系 = 向量空间的平移**：

$$h + r \approx t \qquad \text{（头实体向量 + 关系向量 ≈ 尾实体向量）}$$

「姚明 + 效力于 ≈ 火箭队」。训练让已知三元组满足、未知三元组不满足——**补全**（预测缺失边）与**一致性检验**（发现矛盾事实）由此而来。后续家族：TransH（多关系）、RotatE（关系=复平面旋转）、图神经网络版（R-GCN）。

与向量检索的衔接：KG 嵌入向量可以进向量库——「结构化的语义检索」，比纯文本嵌入多一层关系约束。

## 三、KG 与 LLM 的三种结合

| 模式 | 流程 | 强项 |
|---|---|---|
| **KG 增强检索（GraphRAG）** | 问题 → 实体识别 → 图上多跳扩子图 → 子图序列化进 prompt → 生成 | 关系型/全局型问题（见 RAG 深读的进阶形态） |
| **LLM 增强构建** | LLM 做抽取/对齐/消歧 → 写入 KG | 构建成本骤降（人工审核兜底） |
| **KG 增强训练** | 把三元组作为训练信号（K-BERT 注入、对比学习） | 给模型注入结构化事实、减少幻觉 |

微软 GraphRAG（2024）的补充设计：先对文档社区做**层级摘要**建图，全局性问题（「这批文档的主题」）走「社区摘要检索」而非局部段落——正好补向量 RAG 的最大盲区。

## 四、选型：什么时候值得上 KG

**值得**：关系密集（股权链、供应链、组织架构）、需要审计溯源（金融合规）、知识更新可管控、问题以「谁/哪条链/什么关系」为主。

**不值得**：知识散而乱无 schema 可言、纯语义相似场景、没有持续维护预算——**一个过期的 KG 比没有 KG 更危险**（它看起来很权威）。

## 三·五、知识图谱嵌入家族速览（TransE 之外）

TransE 用平移，后续家族各补一个短板：

| 模型 | 关系的几何 | 补什么 |
|---|---|---|
| TransH | 关系平面上的平移 | 一对多/多对一（实体在不同关系下有不同表示） |
| RotatE | 复平面旋转 | 对称/反对称/组合关系（平移表达不了的） |
| ComplEx | 复数内积 | 对称与非对称关系共存 |
| R-GCN | 图神经网络 | 利用邻域信息（非纯三元组） |

**选型一句话**：关系以「层级/归属」为主（组织架构/分类树）→ TransE 系够用；关系有对称性（配偶/相似）→ RotatE/ComplEx；要利用图结构上下文 → R-GCN/GNN 系（见其深读）。

**KG 与向量检索的融合查询**：实体嵌入入库后可以做「图上多跳 + 向量语义」的混合查询——「找与姚明语义相近、且效力于美国球队的人」：向量管相近、图管效力约束——这是 GraphRAG 进阶形态（结构化过滤 + 语义排序）的底层能力。

## 常见误区

- **「知识图谱 = 结构化的知识库」** —— KG 的核心价值在于**关系推理**（多跳查询/图遍历），不只是「结构化存储」；把 KG 当关系数据库用会浪费其推理能力。
- **「知识图谱构建完成后就是静态的」** —— 真实世界的实体与关系持续演化（公司改名/人物关系变化）；图谱需要增量更新与版本管理——维护成本常高于初始构建。
- **「知识图谱嵌入（TransE）能像词向量一样做类比推理」** —— TransE 的平移假设适用于层级/传递关系，但对称/互斥等关系类型需要不同模型（RotatE/ComplEx）——没有万能嵌入。
- **「GraphRAG 是 RAG 的简单升级」** —— GraphRAG 需要图构建（实体抽取/关系对齐）与图检索（多跳遍历）两层额外工程——成本显著高于向量 RAG，适合关系密集型问题而非通用问答。

## 五、要点总结

1. **三元组与关系表的区别？** 图模型支持变长关系链与图算法遍历；关系表 join 层数固定、跨域扩展难。
2. **TransE 的核心假设？** 关系 = 向量平移 h+r≈t；用于链接预测与一致性检验。
3. **实体消歧为什么是质量关键？** 错误合并/分裂会在图上传播放大（错一条边毒一片子图）。
4. **GraphRAG 补了向量 RAG 什么盲区？** 多跳关系与全局性问题——向量只找「相似段落」，图能走「关系路径」。
5. **KG 的最大成本与最大风险？** 成本=构建与持续更新；风险=过期知识的「权威性谎言」。
6. **LLM 时代 KG 的重新定价？** 抽取成本因 LLM 骤降、价值因幻觉治理上升——净头寸明显变好。
