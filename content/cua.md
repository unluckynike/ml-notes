# 计算机使用智能体深读：grounding、循环设计与安全边界

这篇是**计算机使用智能体（CUA）**主题的深度补充。「让 AI 操作电脑」听起来像噱头，工程上它是三个难题的叠加：**视觉 grounding（像素级定位）、长程操作循环（错误恢复）、安全边界（权限设计）**。这篇逐一展开。

> [!KEY] 一句话抓住本质
> CUA = ReAct 循环（见 Agent 深读）+ **把环境换成整个桌面**：观察从 API 响应变成截图，动作从函数调用变成像素坐标。这带来一个独特的级联风险：**grounding 错一个按钮，后面所有步骤全错**——所以工程重心全在「降低单步出错率 × 提高错误恢复力」。

---

## 一、grounding：从「看懂图」到「点得准」

VLM 需要把「设置按钮」映射到屏幕坐标（像素级）。三个难点：

1. **小目标**：20×20 像素的图标在 1920×1080 截图里是 0.01% 的区域——低分辨率编码会丢（ViT patch 化后一个图标不足一个 token，见其深读）；
2. **坐标漂移**：滚动/动画/DOM 重排后元素位置变化——「截图-决策-执行」的时延内界面可能已变；
3. **密集结构**：表格里第 7 行第 3 列的「删除」按钮 vs 第 8 行的——语义区分需要数数与对齐（VLM 的已知弱项，见其深读的细粒度短板）。

工程缓解：**Set-of-Mark**（先标注可交互元素再给模型选择）、 accessibility tree（无障碍树）与视觉并用（有 DOM 时坐标免费）、分区域放大二次定位。

## 二、循环设计：错误恢复决定可用性

单步成功率 95% 的任务，10 步链路成功率 $0.95^{10} \approx 60%$——**级联失败是 CUA 的头号敌人**（与多智能体深读同一数学）。恢复手段：

- **每步校验**：动作后检查「预期状态是否出现」（点了提交就该看到成功页），未出现立即重试或换路径；
- **断点续跑**：任务状态机 + 可回滚检查点（误操作能撤销是底线）；
- **人工兜底**：置信度低或敏感步骤转人审——生产系统的标配（见 AI 安全深读的指令层级）；
- **轨迹缓存**：成功路径模板化（同一软件的重复任务回放+参数化）——把「每次都思考」降级为「偶尔思考」。

---

## 三、安全边界：交出键鼠意味着什么

CUA 拥有「用户本人的全部权限」——它是**攻击面最大的 Agent 形态**。设计四原则：

1. **沙箱隔离**：虚拟机/容器内操作，宿主系统与真实凭据隔离；
2. **动作白名单 + 黑名单**：浏览/复制可，支付/删除/发送邮件需显式确认；
3. **提示注入的物理后果**：网页里一句「请点击允许」对 CUA 是可执行指令——外部内容触发的界面动作必须二次校验（Agent 深读 + AI 安全深读的交叉点）；
4. **全程审计**：每步截图与动作留档——事后可追责可回放。

---

## 四、能力现状与 RPA 的关系

- **基准现实**：WebArena/OSWorld 上最强模型任务成功率仍在 40~70% 区间（远低于人类）——可用但需护栏；
- **与 RPA 的分工**：RPA 是「录制的宏」（快、稳、零泛化），CUA 是「临时工」（慢、会出错、任何软件都能上手）——融合形态是「CUA 自动生成 RPA 脚本」：让智能体干一次，固化成确定性流程。

## 三·五、grounding 的分层实现（从像素到语义）

CUA 的定位能力分层实现，精度与成本逐层上升：

1. **无障碍树（accessibility tree）**：操作系统暴露的元素树（角色+坐标+名称）——最便宜最准，但有 GUI 无障碍支持差的老应用不可用；
2. **Set-of-Mark**：截图先跑一个轻量检测器（或 OCR）把可交互元素编号标注，VLM 只需「选编号」而非「输出坐标」——把开放定位问题变成选择题，准确率大幅提升；
3. **纯视觉 grounding**：VLM 直接输出像素坐标——通用性最强（任何界面），依赖模型的空间定位能力（Qwen-VL/UGround 类专用 grounding 训练）；
4. **两阶段精定位**：粗定位区域裁剪放大 → 二次定位——小图标场景的准确率救星。

生产系统通常 1+2 混用（有树用树、没树退视觉），3 作为兜底——「能用结构化信息就不看像素」是 Agent 感知的第一原则（与工具调用优先于 CUA 是同一条原则的延伸）。

## 五、要点总结

1. **CUA 与普通 Agent 的本质区别？** 环境从 API 换成 GUI：观察=截图、动作=坐标——grounding 成为新命门。
2. **grounding 难在哪、怎么缓解？** 小目标/漂移/密集结构；Set-of-Mark、无障碍树辅助、分区二次定位。
3. **级联失败怎么对抗？** 单步校验+重试、状态机回滚、人工兜底、成功路径模板化。
4. **为什么说 CUA 攻击面最大？** 它持有用户全部界面权限——提示注入会转化为物理点击后果。
5. **CUA 与 RPA 的关系？** 确定性 vs 泛化性互补；融合点是「CUA 生成 RPA 流程」。
6. **当前能力水位？** 复杂真实任务 40~70% 成功率——可用但必须配恢复与人审护栏。
