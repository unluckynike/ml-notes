# 信息检索深读：BM25 公式的每一项与倒排索引的工程

这篇是**信息检索**主题的深度补充。BM25 用了三十年不大改，公式里每一项都对应一个「如果没有它会怎样」的失败模式。这篇逐项拆解，再讲倒排索引的工程细节与它和向量检索的融合方式。

> [!KEY] 一句话抓住本质
> BM25 = **idf（这个词稀有吗）× tf 饱和（这个词出现得多但收益递减）× 长度归一（长文档不占便宜）**。三个修正分别堵住朴素评分的三个漏洞；倒排索引则是让「亿级文档按词筛候选」在毫秒内完成的数据结构。

---

## 一、公式逐项解剖

$$\text{BM25} = \text{idf}(t)\cdot \frac{tf\cdot(k_1+1)}{tf + k_1\cdot\left(1 - b + b\cdot\frac{|d|}{avgdl}\right)}$$

**① idf（逆文档频率）**：

$$\text{idf} = \log\frac{N - df + 0.5}{df + 0.5}$$

df 是含该词的文档数。「的」出现在几乎每个文档 → idf≈0，不贡献分数；「疫苗」只在 2/5 文档 → 权重高。**没有它会怎样**：查询「的猫」时「的」主导排序。

**② tf 饱和（k₁）**：朴素 TF-IDF 的分数随词频线性涨——文档把「猫」复制 100 遍就能霸榜。BM25 的分子分母设计让贡献随 tf **对数式饱和**：出现 3 次比 1 次分高，出现 30 次不比 3 次高多少。k₁ 控制饱和速度（k₁→∞ 退化为线性，k₁=0 只看出现与否）。

**③ 长度归一（b）**：长文档天然词多、命中多——b 把文档长度相对均值归一：长文档的 tf 贡献打折，b=1 完全归一、b=0 不归一。**没有它会怎样**：长文档在所有查询上霸榜。

三个参数的经验值（k₁≈1.2~2，b≈0.75）三十年几乎没动——**鲁棒到「不需要调」是它长盛的原因**。

## 二、倒排索引：工程细节

```
term          → postings list
「宠物」 → [ (D1, tf=1, pos[2,10]), (D2, tf=1, ...), (D3, tf=1, ...), (D5, tf=1, ...) ]
```

- **构建**：分词 → 每文档词频 → 追加到各词的链表；大规模用分布式构建（MapReduce 的经典案例）；
- **查询**：各查询词取链表 → 按文档 id 归并求交（多词 AND）或并（OR）→ 对候选文档用 BM25 打分——复杂度 O(命中数)，与全库大小无关；
- **压缩**：postings 用 delta 编码 + 变长字节（文档 id 递增，只存差值）——索引体积压到原文 10~20%；
- **中文分词**：词典分词（jieba） vs 子词——分词边界错误直接切掉召回（「支付宝」被切成「支付/宝」仍能召回，切成「支/付/宝」就悬了）。

**查询优化**：常用词（df 巨大）先不取全量链表——用 WAND/MaxScore 算法跳过注定进不了 top-k 的文档，工业引擎的毫秒级秘密。

## 三、与向量检索的融合（RRF）

两路各自排序后融合排名：

$$\text{RRF}(d) = \sum_{\text{通道}}\frac{1}{k + \text{rank}_i(d)},\qquad k\approx 60$$

用排名不用分数（两路分数量纲不可比）；RRF 简单鲁棒，几乎免调参。**何时信谁**：查询含专有名词/代码/型号 → BM25 权重应高；口语化改写/跨语言 → 向量权重高——进阶做法是用查询分类器动态配权。

## 四、面试要点速答

1. **BM25 三个修正各堵什么漏洞？** idf 堵常见词主导、k₁ 饱和堵关键词堆砌、b 归一堵长文档霸榜。
2. **k₁ 和 b 各控制什么？** 饱和速度与长度归一强度；经验值 1.5/0.75 几十年不变。
3. **倒排索引查询复杂度？** O(Σ命中链表长)，与全库规模无关；WAND 跳剪进一步压。
4. **postings 怎么压缩？** delta 编码 + 变长字节——文档 id 只存差值。
5. **为什么 BM25 与向量是互补不是替代？** 字面精确命中 vs 语义泛化——两类失败模式不同，RRF 融合两者。
6. **中文 IR 的关键坑？** 分词边界决定召回粒度；子词/字符级索引是兜底方案。
