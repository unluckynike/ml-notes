# LoRA 深读：低秩适配与高效微调

这篇是**微调与 LoRA**主题的深度补充。LoRA（Low-Rank Adaptation）是开源社区最重要的技术之一——它让「一张消费级显卡微调大模型」成为可能。这里讲清楚：**全量微调的显存都花在哪**、**低秩假设为什么成立**、**秩和超参怎么选**。

> [!KEY] 一句话抓住本质
> 微调引起的那份权重变化 $\Delta W$ 是**低秩的**——用两个小矩阵的乘积 $B A$（$r \ll d$）来参数化它，冻结原权重只训 $A, B$：可训练参数骤降两三个数量级，微调完还能 $W + BA$ **合并回原权重**，推理零开销。

---

## 一、全量微调贵在哪：显存解剖

以 7B 模型、Adam、混合精度训练为例（数字为量级估计）：

| 项 | 大小 | 说明 |
|---|---|---|
| 权重 fp16 | 14 GB | 前向必需 |
| 梯度 fp16 | 14 GB | 反向必需 |
| Adam 状态 m, v（fp32） | 56 GB | **每个参数两个动量**，训练态大头 |
| 激活值 | 视序列/批量 | 反传必需，随上下文长度增长 |

合计 80GB+ 起步——7B 模型全参微调至少一张 80GB 的 A100/H100。注意**优化器状态才是大头**（约 8 字节/参数 vs 权重本身 2 字节）。

LoRA 冻结原权重后：原权重无梯度、无优化器状态；$A, B$ 的参数量是原矩阵的 $2r/d$——$r=8$、$d=4096$ 时约 **0.4%**。7B 模型的 LoRA 状态：几十 MB 到几百 MB 的可训练参数，显存骤降一个数量级。QLoRA 再进一步：把冻结的基座**量化成 4-bit** 加载，微调 7B 只要 ~10GB（游戏显卡可跑）。

---

## 二、方法本身：三行公式

微调 = 给权重找增量 $\Delta W$。LoRA 的假设：

$$\Delta W = B A,\qquad B \in \text{R}^{d\times r},\; A \in \text{R}^{r\times k},\;\; r \ll \min(d, k)$$

前向：

$$h = W_0 x + \frac{\alpha}{r}\,B A x$$

三个细节各有一番道理：

1. **初始化**：$A$ 高斯初始化、$B$ 初始化为**零** → 训练起点 $\Delta W = 0$，模型与基座完全一致（随机初始化 $B$ 会让开局就破坏预训练知识）。
2. **缩放 $\alpha/r$**：$\Delta W$ 的幅度随 $r$ 增大而天然变大（更多秩分量），用 $\alpha/r$ 归一，使得**换 $r$ 时不用重调学习率**。实践中 $\alpha$ 常设为 $r$ 的 1~2 倍。
3. **挂哪里**：原论文只在注意力的 $W_q, W_v$ 上挂。后续共识：**挂所有线性层（含 FFN）通常更好**——单层小 $r$ × 全覆盖 > 集中几层大 $r$，同参数量下效果普遍更强。

```python
# HuggingFace PEFT 的标准用法
from peft import LoraConfig, get_peft_model
cfg = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05,
                 target_modules=["q_proj", "k_proj", "v_proj",
                                 "o_proj", "gate_proj", "up_proj", "down_proj"])
model = get_peft_model(base, cfg)
model.print_trainable_parameters()
# trainable: 0.5% 左右
```

## 三、为什么低秩成立：两个证据

1. **内在维度（intrinsic dimension）**：Aghajanyan 等发现预训练模型的微调更新可以投影到极低维子空间（几百维）而不掉点——**微调不需要那么多自由度**，预训练已把权重放在一个好流形附近。
2. **实证奇异值谱**：把微调前后的 $\Delta W$ 做 SVD，能量高度集中在前几十个奇异值；LoRA 直接用「只学 top-r 子空间」把这个先验硬编码进架构。

直觉：预训练权重 $W_0$ 负责「通用语言能力」（高秩、复杂），微调增量 $\Delta W$ 只负责「风格/领域适配」（方向少、结构简单）。**大而全的冻结，小而专的低秩去学。**

## 四、秩怎么选 & QLoRA

**经验区间**：

| 场景 | 建议 $r$ |
|---|---|
| 风格 / 简单指令格式 | 4~8 |
| 领域知识注入 / 复杂任务 | 16~64 |
| 说话人复刻 / 多任务 | 64~128，同时升 $\alpha$ |

$r$ 加大的收益边际递减，且过大逼近全参微调的过拟合风险（尤其数据少时）。「加大 $r$」和「挂更多层、加数据」相比，后者通常更划算。

**QLoRA 三件套**：

1. 基座加载为 **NF4**（正态分布友好的 4-bit 量化）；
2. **双重量化**（量化常数本身再量化）省 ~0.4 bit/参数；
3. **分页优化器**：显存峰值时把优化器状态换页到内存。
训时 LoRA 梯度反传到 NF4 权重时会反量化成 bf16 计算——精度损失在微调场景可接受（QA 无显著退化，正文见「模型量化」的深度分析思路）。

## 五、部署：训练态与推理态解耦

LoRA 的隐藏王牌：**训完即合并**。

$$W_{\text{merged}} = W_0 + \frac{\alpha}{r}BA$$

合并后就是普通权重——**没有任何推理开销**（对比 prefix/prompt tuning 每步要拼接与额外注意力计算，adapter（Houlsby）每层多两次串行矩阵乘）。这带来运维形态：

- **多适配器热切换**：基座常驻显存一份，客服 LoRA、法律 LoRA 按请求换（vLLM 的 multi-LoRA serving：单基座并发服务几十个适配器）；
- **分发即文件**：一个几十 MB 的 `.safetensors`，社区生态（civitai / HF adapter hub）围绕它生长。

## 六、与近亲的对比

| 方法 | 思路 | 推理开销 | 效果/容量 |
|---|---|---|---|
| **LoRA** | 权重增量的低秩因子 | **零**（可合并） | 主流默认 |
| Adapter（串行小 MLP） | 层间插入瓶颈网络 | 每层串行两次 matmul | 与 LoRA 相当，但慢 |
| Prefix/P-tuning | 只学前缀向量 | 需拼接、占上下文 | 容量小，任务一多互相挤 |
| BitFit | 只调 bias | 零 | 极简任务够用 |
| 全量微调 | 全部参数 | — | 上限最高，最贵 |

> [!TIP] 什么时候仍然要全量微调
> 注入大量新知识（如未见过的语言/领域语料）时，低秩容量成为瓶颈，LoRA 的「知识吸收」明显弱于全参（有研究对比「学新知 vs 学格式」：LoRA 学格式接近全参，学新知识差距大）。**注入知识优先考虑 RAG，改变行为用 LoRA**——这个分工与 RAG 主题的结论互相印证。

## 七、面试要点速答

1. **LoRA 为什么省显存？** 冻结权重没有梯度与优化器状态（后者是全参微调的大头），可训练参数降两个数量级。
2. **为什么 B 初始化为零？** 保证起点 $\Delta W=0$，不破坏基座；A 零初始化会导致梯度对称死亡，所以 A 用高斯。
3. **$\alpha/r$ 的作用？** 归一化 $\Delta W$ 幅度对 $r$ 的依赖，换秩不用重调学习率。
4. **LoRA 与 Adapter 的本质区别？** LoRA 改「权重的增量」且可合并（推理零开销）；Adapter 改「结构本身」（永远多算）。
5. **LoRA 学新知识为何弱？** 低秩容量限制——行为适配是低秩的，知识记忆是高秩的；新知识应走 RAG 或全参微调。
6. **QLoRA 训练时 4-bit 权重怎么反传？** 前向/反向时按需反量化 NF4→bf16 计算，梯度只流向 LoRA 因子；存储保持 4-bit。
