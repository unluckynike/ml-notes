# MoE 深读：稀疏激活与路由的工程学

这篇是 **MoE 混合专家**主题的深度补充。MoE 是当代大模型「扩大参数而几乎不增加每 token 计算量」的关键结构（Mixtral、DeepSeek-V3、GPT-4 据传都用）。核心难题只有一个：**路由怎么训练**——可微的稀疏选择是个矛盾，负载均衡是个博弈。

> [!KEY] 一句话抓住本质
> MoE 层 = 一个**门控网络**把每个 token 送给 Top-K 个「专家 FFN」中的 K 个（常 K=2，从 8~256 个专家里选）——参数总量巨大，但每个 token 只经过 K 份计算。**条件计算**让「知识容量」与「计算成本」解耦，代价是路由训练与显存占用（所有专家都得驻留）。

---

## 一、结构与一次前向

$$y = \sum_{i \in \text{TopK}(g(x))} g_i(x)\cdot E_i(x),\qquad g(x) = \text{softmax}(W_g x)$$

- 专家 $E_i$ 通常是结构相同的 FFN（不同初始权重，训练中自然分工）；
- 门控取 Top-K（K=1~2 常见），只有被选中的专家执行计算——**每 token FLOPs ≈ 稠密模型的 K/N + 注意力开销**；
- 门控权重 $g_i$ 作为混合系数（softmax 后再取 TopK 的稀疏版）。

**关键设计动机**：模型的「知识」存在参数里（希望多），计算是每 token 的（希望少）——MoE 用 N 倍参数、约 1 倍计算，换来在同等推理成本下明显更高的容量上限。实测（Mixtral 8×7B）：47B 总参数、每 token 约 13B 激活，性能对齐更大稠密模型。

---

## 二、路由训练的两大病与药

**病 1·不均衡（赢家通吃）**：早期某几个专家「运气好」被多选 → 训得更好 → 更被多选——正反馈崩盘，其余专家变成死参数。

- **药 A·辅助负载均衡损失**：惩罚专家被选频率的离散度

$$L_{bal} = \alpha\cdot N\sum_{i=1}^{N} f_i\cdot \bar{g}_i$$

（$f_i$=专家 i 被选中的 token 比例，$\bar g_i$=平均门控概率——两者都均匀时最小）；
- **药 B·噪声与容量因子**：路由加噪声扰动、每专家设 token 容量上限（超了丢弃/下一层补）。

**病 2·不可微的 TopK**：选与不选是离散的——梯度只流过被选专家（稀疏激活的「硬」选择），门控的梯度靠被选者的加权系数传递；训练不稳定常来自这个半离散结构（各种 sigmoid/软路由变体试图缓解，但硬 TopK 仍是主流——简单且推理确定）。

**专家分工是涌现的**：训练后发现专家自然分工（按句法、领域、任务类型），但**不是设计出来的**——也不必强求「人类可解释的分工」。

## 三、工程账本

| 项 | 稠密模型 | MoE |
|---|---|---|
| 显存（部署） | 参数×字节 | **全部专家都要驻留**（8×7B≈47B 参数的显存） |
| 每 token 计算 | 正比参数 | 只 K 个专家 |
| 训练显存 | 大 | 更大（专家+路由+均衡损失） |
| 批量友好 | 好 | 路由使专家负载不均，需 capacity/丢弃处理 |

推论：**MoE 适合「算力贵显存便宜」的推理服务**（吞吐大增）；消费级单卡部署反而吃不消（显存放不下）——量化（专家权重 4bit）与专家卸载/按需加载是端侧 MoE 的研究方向。

## 三·五、Mixtral 的账本与细粒度专家的演进

Mixtral 8×7B 的实际数字：47B 总参数、每 token 激活 ~13B——**容量对齐 47B 稠密、成本对齐 13B 稠密**。它为什么选 8 个大专家（而非 64 个小的）？早期结论是「专家数量边际收益低、路由开销小」；DeepSeek-V3（2024）反其道：**细粒度专家**（256 个小专家，每 token 激活 8 个）+ 共享专家（所有 token 必经的公共专家）——粒度细了，组合数爆炸，同等激活量下容量上限更高。

**专家并行的通信问题**：MoE 层需要 All-to-All 通信（token 按路由结果分发到对应专家所在卡）——比 DP 的 All-Reduce 更难调度（负载不均时长尾卡）。训练框架（Megatron-MoE）的核心工程就是 overlap All-to-All 与计算。

**「专家分工」的正确解读**：可解释性研究（Mixtral 的路由分析）发现专家按「表层特征」（token 位置/标点/数字）分工的程度高于「语义主题」——「一个专家管数学」的直觉基本不成立；负载均衡损失强制的是「均匀」，模型自发涌现的是「统计均衡 + 浅层语义混杂」——解读专家分工要谨慎。

## 四、面试要点速答

1. **MoE 怎么做到参数大计算小？** Top-K 路由的条件计算：每 token 只激活 K/N 的专家。
2. **路由为什么训练不稳？** 赢家通吃的正反馈 + TopK 不可微；解法：负载均衡辅助损失、路由噪声、容量因子。
3. **均衡损失惩罚什么？** 专家被选频率与门控概率的偏离均匀程度。
4. **MoE 部署的主要成本？** 全部专家驻留显存——省的是计算不是显存。
5. **K 取多少？** K=1/2 主流：计算省；K 大一点性能略升但边际差（DeepSeek-V3 用细粒度专家+K=8 的折中）。
6. **与集成学习的区别？** 集成是「同任务多模型平均」，MoE 是「同模型内条件分工」——后者是单个前向里的稀疏激活。
