# AI 搜索深读：引用生成、评估与信任工程

这篇是 **AI 搜索引擎**主题的深度补充。演示里跑通了四步管线，这篇讲生产级的三个深水区：**引用对齐的工程细节**、**AI 搜索怎么评估**（比 RAG 更难）、以及**信任工程**（为什么「可溯源」是产品的生死线）。

> [!KEY] 一句话抓住本质
> AI 搜索与传统 RAG 的差别在「开放网络」三个字：语料不是你的企业库而是整个互联网（新鲜度、SEO 垃圾、对抗性内容都要处理）；答案不是「帮你查资料」而是「直接给你结论」——**结论的可信度必须靠逐句引用来背书**。工程的重心从「检索准」移到「引用实」。

---

## 一、管线各段的生产细节

**① 查询理解与改写**（决定召回上限）：

- 口语→检索语言（「维C一天吃多少」→「维生素 C 每日推荐摄入量」）；
- 意图分类（导航型/信息型/事务型）决定管线分支（导航型直接给官网卡片，不走生成）；
- 复杂问题拆解：「A 和 B 哪个更适合新手」→ 检索 A 特点 + B 特点 + 新手需求三个子查询（agentic 多轮检索的雏形）。

**② 混合检索**（见信息检索深读）：网页索引的新鲜度分层（新闻要小时级、百科要天级）；**SEO 垃圾过滤**（AI 内容农场生产的「为排名而生」的低质内容是最大污染源——质量分类器 + 域名信誉）。

**③ 重排**：交叉编码器精排 + **多样性去重**（top-3 全是同一观点的复述会让答案片面——MMR 式多样性）+ 一致性聚合（多来源都说的可信度更高）。

**④ 引用生成**：见下节。

**AI 搜索管线伪代码**——每个引用都要能指回原文的具体段落：

```python
def ai_search(query):
    q = rewrite(query)                           # 意图澄清 + 拆分
    docs = hybrid_retrieve(q, k=50)              # BM25 + 向量召回
    passages = rerank(q, docs, top=8)            # 交叉编码器精排
    answer = llm_generate(q, passages,
                          rule="每个论断标注 [1][2] 引用编号")
    aligned = verify_citations(answer, passages) # 引用与原文对齐校验
    return answer if aligned else llm_generate(q, passages, stricter=True)
```

## 二、引用生成与对齐：可信度的技术实现

**基本协议**：检索片段编号 → 生成时要求逐句标注 [编号] → 后处理校验：

1. **存在性**：引用编号是否真的在检索结果里（防编造引用）；
2. **支持性**：被引用片段是否真的支持该句主张——用一个 NLI（自然语言推理）模型判「蕴含/中立/矛盾」——**矛盾引用直接重生成**；
3. **覆盖性**：答案的关键主张是否都有引用（无引用的主张要么删掉要么标「未经证实」）。

**归因的粒度**：句子级引用是产品标配；进阶是「片段高亮」（点击引用高亮来源里的具体句子）——用户验证成本越低，信任越高。

**引用与生成质量的张力**：强约束「只说有引用的话」会让回答保守琐碎；放松则幻觉回流。工程折中：事实性主张必须带引用，观点/总结性内容明确标注「综合以下来源」。

## 三、怎么评估 AI 搜索（比 RAG 难一层）

| 层 | 指标 | 说明 |
|---|---|---|
| 检索层 | 召回/排序质量 | 同 RAG（见其深读的评估分层） |
| **引用层** | 引用精确率（引用的支持率）、引用覆盖率（主张被引用的比例） | AI 搜索特有 |
| 答案层 | 忠实性（答案↔引用一致）、完整性（覆盖子问题的比例） | 用 LLM-as-judge + 人工抽检 |
| 产品层 | 点击引用率、改问率（用户对答案不满重问）、留存 | 真实信任的行为信号 |

**对抗性评测**：故意检索 SEO 垃圾/互相矛盾的信源，看系统能否识别并处理（信源冲突时怎么办：并列呈现比武断裁决更可信）。

## 常见误区

- **「检索到的都是对的，生成只是组织语言」** —— 检索结果可能过时、矛盾或错误；生成模型还可能忽略检索内容自由发挥。可信的答案需要「检索质量 + 忠实生成 + 引用验证」三层保障。
- **「引用编号存在就等于答案可信」** —— 引用幻觉的高级形态：引用了真实来源但**该来源不支持那句话**。需要支持性校验（NLI 或人工抽检），不能只查编号存在。
- **「语义检索可以完全取代关键词检索」** —— 语义检索对精确 token（错误码/型号/法条编号）弱——混合检索（BM25+向量）是工程标配，不是可选项。
- **「查询改写是一次性的」** —— 复杂问题需要多轮改写与迭代检索（Self-RAG/Deep Research 模式）：第一次检索的结果会揭示「还需要查什么」。

## 四、要点总结

1. **开放网络三难**：新鲜度、垃圾过滤、对抗性内容——企业 RAG 没有的问题。
2. **引用三验**：存在性、支持性（NLI）、覆盖性——缺一层就有「引用幻觉」。
3. **迭代搜索**：模型自查信息充分性，不足则生成新查询——agentic 循环是 Deep Research 的核心。
4. **信源冲突处理**：并列呈现比武断裁决更可信——矛盾是信号不是噪音。
5. **评估四层**：检索/引用/答案/产品行为——引用层是 AI 搜索的特有考验。
6. **信任工程**：用户验证引用的成本越低（片段高亮），产品的可信度越高。
