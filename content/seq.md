# 序列预测深读：窗口、状态与两种建模范式

这篇是**序列预测·时间序列**主题的深度补充。时间序列预测有两个并行传统——**统计模型（ARIMA 族）**与**机器学习/深度模型（窗口监督化、RNN、Transformer）**——这篇讲清两者的建模哲学差异、监督化的正确姿势，以及「预测多步」这个被低估的难题。

> [!KEY] 一句话抓住本质
> 一切序列预测的核心问题只有一个：**如何表示「历史」**。统计模型把历史压缩成几个系数（自回归+移动平均的解析结构）；ML 把历史切成固定窗口当特征（监督学习化）；RNN/SSM 把历史压进一个状态向量。三种压缩方式各有失效域——**选模型的本质是选「历史表示」**。

## 一、监督化：滑窗的正确姿势

把序列 $(x_1,\ldots,x_T)$ 变成监督学习数据集：

```
X = [x_{t-w}, ..., x_{t-1}]  →  y = x_t     （单步，w 为窗口）
```

三个常错的细节：

1. **特征与目标的时间对齐**：特征必须严格 « 截至 t−1 已知 »——把 t 时刻的信息漏进特征就是泄漏（时间序列第一大坑）；
2. **验证切分必须按时间**：随机切分 = 用未来预测过去，分数虚高（见模型评估深读）；正确姿势是滚动/扩展窗口验证（expanding/rolling origin）；
3. **特征工程**：滞后特征（lag）、滚动统计（均值/方差/差分）、日历特征（星期/节假日）——树模型靠这些吃饭；线性模型加正弦特征处理周期。

**单步 vs 多步**：多步预测三种策略——递归（预测值滚回输入，误差累积）、直接（每个 horizon 单独一个模型，独立但贵）、seq2seq（一次输出整段，深度学习主流）。

**把任务写成一行概率**——序列到序列建模的是条件链式分解，「解码」就是在这条链上找高分序列：

$$P(y_1, \dots, y_T \mid x) = \prod_{t=1}^{T} p(y_t \mid y_{<t}, x), \qquad \hat{y} = \argmax_{y} \; \sum_{t=1}^{T} \log p(y_t \mid y_{<t}, x)$$

精确求 argmax 是 NP 难的（每一步的选择都改变后续所有分布）——beam search 用「只保留 log 分数最高的 B 条前缀」近似。实用系统还要做**长度惩罚**：每个 token 的 log 概率都小于 0，序列越长分数越低，模型会偏爱短输出——所以把分数除以 $T^{\alpha}$（$\alpha \approx 0.6$）再比较。

**beam search 二十行**——每步只保留 log 分数最高的 B 条前缀，近似解出链式 argmax：

```python
import numpy as np
rng = np.random.default_rng(0)
vocab = ["我", "的", "猫", "爱", "鱼", "<eos>"]

def next_token_dist(prefix):                         # 玩具模型：伪分布（真实系统来自模型 softmax）
    logits = rng.normal(size=len(vocab))
    logits[vocab.index("<eos>")] -= 2.0 if len(prefix) < 3 else 1.0   # 短句不想停
    e = np.exp(logits - logits.max()); return e / e.sum()

def beam_search(B=3, max_len=5):
    beams = [([], 0.0)]                              # (序列, 累计 log 概率)
    for _ in range(max_len):
        cand = []
        for seq, sc in beams:
            if seq and seq[-1] == "<eos>": cand.append((seq, sc)); continue
            p = next_token_dist(seq)
            for v, pv in zip(vocab, p): cand.append((seq + [v], sc + np.log(pv + 1e-12)))
        beams = sorted(cand, key=lambda x: -x[1])[:B]   # 只留 top-B：指数空间 → 线性
        if all(s[-1] == "<eos>" for s, _ in beams): break
    return max(beams, key=lambda x: x[1])

best, score = beam_search()
print("最优序列:", "".join(best), "| log 分数:", round(score, 2))
# 对比贪心（B=1）与 B=5：B 越大越接近真 argmax，但计算量线性涨——B 是质量/成本旋钮
print("贪心(B=1):", "".join(beam_search(B=1)[0]))
```

## 二、两大传统的哲学对比

| 维度 | 统计（ARIMA/ETS） | ML/DL（树/RNN/Transformer） |
|---|---|---|
| 结构假设 | 显式（ARIMA 的线性递归） | 隐式（数据自己说） |
| 数据需求 | 小（几十个点也能用） | 大（树要特征、DL 要长序列） |
| 外推 | 结构保证（趋势/季节项明确） | 外推不可控（树不能外推！） |
| 可解释 | 强（系数=弹性、季节项可见） | 弱 |
| 多变量/外部特征 | 弱（VAR 扩展有限） | 强（任意特征拼接） |

> [!WARN] 树模型不能外推
> 回归树的预测是训练目标值的凸组合——**永远不会预测出训练范围外的值**。有趋势的序列交给 XGBoost，趋势全被「封顶」在历史最大值。解法：对 y 做差分/去趋势再喂树，或换线性+树的组合（如 Prophet 的分段线性 + 季节项 + 回归器）。

## 三、深度序列模型的位置

RNN/LSTM 把历史压进 O(1) 状态（流式友好，见 RNN 深读）；Transformer 全并行但 O(n²)（长序列贵，见其深读）；**SSM/时间卷积**折中。时序场景的工程事实：

- 长序列Transformer 在「窄数据」（每个序列样本少）上常输给强特征+GBDT；
- 深度模型的赢面在**多变量、多序列共享模式**（千店销量联合预测）——单序列小数据永远是统计模型主场；
- 不确定性区间：分位数损失/共形预测（见其深读）是标配。

**M 竞赛的启示**：历届冠军（如 M5）都是「强特征 + LightGBM」打败花哨深度架构——时序比赛的真理是特征工程与验证纪律，不是模型新奇度。

## 常见误区

- **「时间序列预测 = 把历史数据扔给模型」** —— 时间序列有特有的预处理需求：平稳性检验/差分、季节性分解、趋势处理——不处理这些直接建模会学到「伪模式」。
- **「LSTM/Transformer 一定优于传统统计方法（ARIMA）」** —— 在数据量小、模式简单、可解释性重要的场景，ARIMA 仍然是有力基线——深度学习需要大量数据才能发挥优势。
- **「多步预测 = 单步预测的多次重复」** —— 多步预测的误差会**累积**（递归策略）或需要**直接多输出**（序列到序列）——单步准确不等于多步准确（误差传播是非线性放大）。
- **「时间序列的交叉验证就是普通 K-fold」** —— 时序数据有时间依赖性——K-fold 打乱时间顺序导致**信息泄漏**（用未来预测过去）；必须用前向滚动/扩展窗口验证。

## 四、要点总结

1. **时间序列验证为什么不能随机切分？** 泄漏未来；用滚动起点验证模拟真实部署。
2. **多步预测三种策略？** 递归（误差累积）、直接（贵而独立）、seq2seq（并行输出）。
3. **为什么树模型要差分？** 树不能外推出训练值域；去趋势后树学「变化量」。
4. **ARIMA 的 AR/I/MA 各是什么？** 自回归（对历史值回归）、差分（去趋势）、移动平均（对历史噪声回归）——见 ARIMA 深读的推导。
5. **单序列小数据选什么？** 统计模型（ARIMA/ETS/Prophet）+ 置信区间；深度模型需要跨序列共享模式才有优势。
6. **平稳性为什么重要？** 统计模型的参数假设分布不随时间变；不平稳先差分/变换（ARIMA 的 I 的由来）。
