# 多智能体深读：拓扑、模式与「什么时候不该用」

这篇是**多智能体协作**主题的深度补充。「多个 Agent 一起干活」听起来强大，但工程真相是：**多智能体用通信成本换分工收益，很多场景是亏本买卖**。这篇讲清主流拓扑与协作模式，以及最重要的——适用边界。

> [!KEY] 一句话抓住本质
> 多智能体系统 = 把「一个提示词里塞不下的复杂任务」拆给多个有角色、有记忆、有工具的 Agent。核心收益是**分而治之**（每个 Agent 上下文聚焦、互不污染）与**对抗性检验**（互相评审发现问题）；核心成本是**通信开销与级联失败**——每多一个环节，错误率乘一次。

---

## 一、拓扑：谁跟谁说话

| 拓扑 | 结构 | 特点 |
|---|---|---|
| **中心化编排（Orchestrator）** | 一个主 Agent 派活、汇总 | 可控、可调试，主流生产形态（crew/swarm 多为此类） |
| **流水线** | A 的输出是 B 的输入 | 适合阶段明确的任务（写→审→改） |
| **去中心化对话** | 平等轮转发言 | 「圆桌辩论」，最能暴露分歧也最难收敛 |
| **分层** | 管理层-执行层-工具层 | 大规模系统的组织学（模拟公司/军队） |

选型直觉：**先中心化**（可控性最好），辩论类需求再上对话式，生产慎用自由对话（失控与 token 黑洞）。

---

## 二、四种被验证有效的模式

1. **生成-评审（Actor-Critic 式）**：写代码的 Agent 配一个只挑毛病的 Reviewer。评审者上下文里只有「评审清单」，比同一个模型自己改自己更客观——**角色隔离是多智能体最稳的收益**。
2. **辩论（Debate）**：多个 Agent 就同一问题独立作答再互相反驳，取收敛结论。研究显示对事实性与推理有稳定提升（相当于 Self-Consistency 的增强版：独立上下文让观点真正多样化）。
3. **专家会诊**：数据库专家、前端专家、安全专家各自审查同一 artifact——把「一个人检查所有维度」拆成并行专项。
4. **群体模拟**：模拟用户群/社会（Generative Agents）做产品调研、社会科学实验——目标不是「任务完成」而是「涌现行为」。

## 三、成本账：什么时候不该用多智能体

一个错误率各 10% 的三环节流水线，端到端成功率 $0.9^3 \approx 73%$——**级联失败是乘法的**。加上：

- **Token 成本**：每轮广播上下文，成本随 Agent 数与轮数乘积增长；
- **延迟**：串行环节逐个累加；
- **责任漂移**：「这个问题归那个 Agent 管」——每个都以为别人会查。

**决策清单**（满足其一才上多智能体）：

- 单 Agent 上下文装不下任务所需的信息/工具（超长文档 + 多工具域）；
- 需要**对抗性**（评审、辩论）提升质量；
- 需要**并行**（多个独立子任务可同时跑）；
- 需要**角色隔离**（生成与评判必须不同上下文）。

其余情况：一个结构化提示 + 好工具 + 循环内自检的单 Agent，通常更便宜、更稳、更好调试——这也是 Anthropic《Building Effective Agents》的核心结论。

> [!TIP] 工程要点
> - Agent 间传递**结构化产物**（JSON/文件），不传闲聊——上下文是稀缺资源；
> - 每个子 Agent 设独立预算与超时；
> - 全链路 trace：谁说了什么、调了什么工具——没有可观测性就没有调试。

## 四、面试要点速答

1. **多智能体的核心收益与代价？** 收益：上下文聚焦、角色隔离、并行、对抗检验；代价：通信 token、延迟、级联失败（错误率相乘）。
2. **编排式与对话式的区别？** 中心化编排可控可调试、生产主流；自由对话能暴露分歧但难收敛、贵。
3. **辩论为什么能提升事实性？** 独立上下文产生真正多样的观点，相互反驳抵消单模型的自信偏差（Self-Consistency 的社会化版）。
4. **什么时候单 Agent 更好？** 任务单线、上下文装得下、不需要对抗检验——简单提示工程+工具循环更稳更省。
5. **Agent 间通信设计原则？** 传结构化产物而非自由文本；接口明确（输入 schema/输出 schema）；有终止与预算。
6. **如何评估多智能体系统？** 端到端任务成功率 + 分环节归因（哪个环节错最多）+ 成本/任务；trace 是前提。
