# 数学推理深读：级联错误、工具增强与形式验证

这篇是**数学推理**主题的深度补充。上面标签页用蒙特卡洛展示了「心算/竖式/工具」的指数差距，这篇把三条改进路线——**分步、工具、形式化**——各自的机理与边界讲清，并回答「LLM 会做数学吗」这个问题的严格版本。

> [!KEY] 一句话抓住本质
> LLM 做数学的三层失败：**算术层**（逐 token 采样天然不可靠，错误随位数指数级联）、**推理层**（方向可能错，需要反思与验证兜底）、**形式层**（自然语言证明有歧义，只有形式系统能给「可判定」的正确性）。三条路线分别攻击一层：CoT 攻推理、工具攻算术、Lean 攻形式。

---

## 一、算术层：级联错误的数学

逐位运算正确率 p，n 位复合运算全对 ≈ p^n。关键数字：p=0.93 的「心算」，8 位运算正确率只剩 0.94^16≈37%…… **这不是「模型笨」，是自回归采样的本性**——每个 token 是一次有噪声的抽样，误差必然级联。

两条修补路线的本质都是「抬底数」：

- **CoT 分步**：把复合运算拆成个位乘加，p 从 0.93 抬到 0.997——但仍是概率的，位数大了照样塌（o1/R1 的长思考 + 自我验证是在继续抬 p）；
- **工具调用**：把算术外包给解释器，底数≈1——**正确率从概率问题变成工程问题**。代价：模型要「知道该算什么」（语义层不能外包）。

## 二、工具增强：PoT 范式

Program-of-Thoughts（PAL）：模型输出「怎么算」的代码而非答案本身：

```python
# 问：3 年前小明是妹妹年龄的 3 倍，现在和是 24，妹妹现在几岁？
sister_now = (24 - 2*3) / (3 + 1)   # 解方程交给解释器
```

分工清晰：**建模/列式归 LLM（语义强项），执行归解释器（确定性）**。GSM8K 上 PoT 比 CoT 高 10~15 个百分点，且随问题算术复杂度拉大。

**验证层**（第三道保险）：自验证（让模型重算/反向验算）、多数投票（Self-Consistency，见思维链深读）、执行反馈（代码报错即重试）——现代推理模型的三件套。

## 三、形式验证：从「像对」到「可证明」

自然语言数学的根本缺陷：**歧义**（「显然」「同理」藏着跳步）与**不可判定**（人也无法确定对不对）。形式化系统（Lean/Metamath/Coq）把证明写成机器可检查的项：

- **AlphaProof（2024）**：LLM 提议证明步骤 + Lean 检查正确性 + MCTS 搜索证明树——IMO 银牌水平。范式 = 「神经提议 + 符号验证 + 搜索」；
- **自动形式化（autoformalization）**：把自然语言题目翻译成 Lean——目前是最薄弱的环节（翻译错则全错）；
- 局限：形式库覆盖有限（竞赛组合数学、几何）；人类数学的大部分（如分析中的「标准论证」）形式化成本极高。

## 四、与推理模型的分工（2025 年的格局）

| 场景 | 首选 |
|---|---|
| 应用题/文字数学 | CoT/长推理 + PoT 工具 |
| 数值密集计算 | 直接写代码执行 |
| 需要证明的定理 | Lean 管线（AlphaProof 类） |
| 日常估算 | 模型直答 + 量级校验 |

## 三·五、可验证奖励的边界：什么数学任务适合 RLVR

RLVR 的奖励必须是**程序可判定**的，数学任务按「可验证性」分三档：

| 档位 | 判定方式 | RLVR 适用性 |
|---|---|---|
| 计算题（数值答案） | 精确匹配/区间容差 | 完美适用（GSM8K/MATH 的主力） |
| 证明题 | Lean/形式系统检查 | 适用于形式化后的（AlphaProof 路线） |
| 开放探索/建模 | 无唯一答案 | **不适用**（需要人类或 PRM） |

两个工程细节决定 RLVR 成败：

1. **答案提取的鲁棒性**：模型答案藏在自由文本里（「所以答案是 **42** 啦」）——提取器（正则/LLM 抽取）的错误会错杀正确答案，让 RL 学会「排版答案」而非「做对题」；
2. **难度课程**：奖励全 0（题太难）或全 1（太简单）都没有梯度信号——按 pass rate 动态配题（curriculum），把训练保持在「有梯度带」里（DeepSeekMath 的实践）。

**与 PRM 的分工**：ORM（结果奖励）只能判对错；PRM（过程奖励）给每步打分——推理时用 PRM 引导搜索（best-of-N 按步骤加权），训练时用 PRM 提供更密集的信号——OpenAI 的 Let's Verify Step by Step（2023）实测 PRM 在 MATH 上显著优于 ORM。

## 五、要点总结

1. **为什么 LLM 算术不可靠？** 自回归逐 token 采样有噪声，n 位运算错误 p^n 级联——本性而非 bug。
2. **PoT 为什么比 CoT 准？** 语义与计算解耦：算术底数从 0.93 → 1；模型只负责列式。
3. **AlphaProof 的三件套？** 神经提议 + Lean 形式验证 + 搜索——把「像对」升级为「可证明」。
4. **自验证怎么做？** 反向验算/重算、Self-Consistency 投票、执行反馈重试——抬有效 p 的工程手段。
5. **形式化的瓶颈在哪？** 自动形式化（自然语言→Lean）与库覆盖；翻译错则验证空转。
6. **「LLM 会做数学吗」的严格答案？** 语义与策略层面接近人类水平（RLVR 后），算术层依赖工具，严格证明依赖形式系统——三层能力不同质。
