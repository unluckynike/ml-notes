# 多模态大模型深读：VLM 的三种接线方式

这篇是**多模态大模型 VLM**主题的深度补充。上面标签页给了「ViT + 投影层 + LLM」的标准配方，这篇讲清**三种接线方式（投影/交叉注意力/统一 token 化）的取舍**、**视觉 token 数量的账本**，以及 VLM 最著名的病——幻觉为什么更隐蔽。

> [!KEY] 一句话抓住本质
> VLM 的全部问题 = 「把图变成 LLM 能吃的序列」。三种方案对应三个时代：**线性投影**（LLaVA：便宜、够用）、**交叉注意力**（Flamingo：冻结两边、灵活注入）、**原生多模态**（GPT-4o：统一 token 从头训）。视觉 token 的数量决定成本曲线——一张高清图 = 几千 token 的账单。

---

## 一、三种接线方式

| 方案 | 结构 | 代表 | 取舍 |
|---|---|---|---|
| **投影式** | ViT 特征经 MLP 映到 LLM 词向量空间，拼接进上下文 | LLaVA、Qwen-VL | 最简单、生态最好；视觉 token 占上下文 |
| **交叉注意力** | LLM 冻结，视觉经 cross-attention 注入 | Flamingo、LLaVA-NeXT 变体 | 不动 LLM 权重、可插拔；架构复杂些 |
| **原生统一** | 图像也过 tokenizer，从头多模态预训练 | GPT-4o、Gemini | 模态融合最深（早期融合）；训练成本天文数字 |

**LLaVA 的极简配方值得记住**：GPT-4 生成视觉指令数据（让文本 LLM 看着 caption 写问答）→ 冻结 ViT 与 LLM 只训一个线性投影 → 就能让 7B 模型看图问答。**「数据合成 + 最小可训参数」**的教科书案例。

**视觉 token 数的账本**：ViT 每 14×14 像素一个 patch，672² 的图 = 48×48 = 2304 个 patch；任何分辨率策略（切图/池化/Q-Former 压缩到 32/64 个）都是在「细节保真」与「上下文占用」之间权衡。**高分辨率 OCR 类任务必须多 token，闲聊类任务可以极省**——动态分辨率（按图的内容决定 token 数）是当代主流。

## 二、训练：两阶段与对齐的本质

1. **阶段一·对齐预训练**：图文对（caption 数据），训投影层——目标只是「让视觉 token 的语言学位置正确」（视觉词嵌入的冷启动）；
2. **阶段二·指令微调**：多模态指令数据（问答/OCR/图表推理），解冻 LLM（或 LoRA）——任务能力由此而来。

**「对齐」在对齐什么？** CLIP 的对齐是**检索式**（两塔 embedding 靠近）；VLM 的对齐是**生成式**（视觉 token 要在 LLM 的自回归循环里真正「参与推理」）——后者要求投影后的分布落在 LLM 表示空间「正确的流形」上，两阶段训练就是为此。

## 三、VLM 的病：幻觉更隐蔽

文本 LLM 幻觉是「编造不存在的事实」；VLM 多一层「**看着图编**」——模型对问题给了先验答案，图像证据只做装饰（「图里有三个人」其实两个——语言先验碾压视觉证据）。

- 根源之一：训练数据里 caption 的语言模式强（「一张照片里有…」），模型学会套路生成；
- 评测：POPE（按图问「有没有 X」）、HallusionBench（语言先验陷阱题）；
- 缓解：训练数据去偏、要求先「描述再回答」的 CoT、检索增强（把视觉细节转成文本证据）。

**细粒度空间任务的弱项**（计数、精确位置）来自两个结构性原因：patch 化丢像素级精度 + 文本自回归对空间布局的天然低效——专用视觉模块（SAM 式、坐标 token）是补丁。

## 三·五、多图与视频输入、以及训练数据的生产

**多图输入的三种语义**：对比（哪张图的构图更好）、引用（第二张图里的人穿什么）、组合（把这两张的元素合成描述）——训练数据的构造要显式覆盖这些模式（多图 QA 对），否则模型只见过「一图一答」会泛化失败。视频输入（Qwen-VL-Video/InternVideo）= 多图的极限形态，核心是帧采样与时间 token 预算（见视频理解深读）。

**视觉指令数据的生产流水线**（LLaVA 式的自我强化）：

1. 用 caption 模型给图打详细描述；
2. 让文本 LLM 基于 caption 生成问答对（GPT-4 生成、开源模型复现）；
3. 过滤（去重/长度/质量分类器，见数据工程深读）；
4. 用生成的数据训投影层+LLM。

**「描述先于回答」的幻觉抑制**：让 VLM 先输出「图中可见：…」再回答问题——强制回答条件于显式描述，幻觉率显著下降；代价是延迟与 token。这是 CoT（见思维链深读）在多模态的具体化：**中间产物（描述）就是答案的证据链**。

## 常见误区

- **「VLM 看到了图像的每个像素」** —— 视觉编码器将图像压缩为少量视觉 token（每个 token 代表一个 patch 的语义摘要）——分辨率/细节/密集小文字的信息在压缩中大量丢失。
- **「VLM 的幻觉只出现在描述不存在物体」** —— VLM 幻觉还包括：错误的计数/空间关系（左/右）/属性绑定（把 A 的颜色说成 B 的）/忽略负面证据（图中没有但文本暗示有的内容）——幻觉类型比「编造物体」更多样。
- **「给 VLM 更多分辨率一定提升理解」** —— 高分辨率增加成本（更多视觉 token）但可能**降低**全局理解能力（注意力被局部细节稀释）；高分辨率有利于 OCR/细节但不利于场景理解。
- **「VLM 可以替代专业的视觉模型（检测/分割/OCR）」** —— VLM 是通用视觉理解，在专业任务上精度不及专用模型（YOLO 检测、SAM 分割、PaddleOCR 文字）——VLM 适合「理解与对话」，专用模型适合「精确输出」。

## 四、要点总结

1. **三种接线的取舍？** 投影（简单生态好）/ 交叉注意力（可插拔）/ 原生统一（融合深、成本高）。
2. **LLaVA 配方为什么便宜有效？** 合成指令数据 + 只训投影层——冻结骨干学「接口」。
3. **视觉 token 数量的账？** patch 数 = (分辨率/14)²；OCR 要数千 token、聊天可压缩——动态分辨率是主流。
4. **两阶段各训什么？** 对齐预训练训投影（视觉冷启动），指令微调解冻 LLM（任务能力）。
5. **VLM 幻觉为什么更隐蔽？** 语言先验碾压视觉证据，「看着图编」比纯编造更难被用户识破。
6. **为什么 VLM 数不清物体？** patch 化的粒度损失 + 自回归文本对空间计数低效——需要专用模块补。
