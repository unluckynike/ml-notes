# 水印与内容检测深读：绿名单数学、攻防与合规版图

这篇是**水印与内容检测**主题的深度补充。演示里「δ 与改写攻击」的博弈，这篇把三块讲透：**绿名单水印的完整数学**、**攻击面的系统分类**、以及**合规版图**（各国法规与技术能力的对照）。

> [!KEY] 一句话抓住本质
> 软水印的本质是**把「模型身份」编码进 token 的统计分布**：单个 token 看不出任何异常，几十上百个 token 的统计偏向（绿名单占比）却能被假设检验捕获。它是「机器可验证的出处证明」，不是「防伪印章」——攻防天生的不对称决定了它的定位是「提高滥用成本」而非「绝对防伪」。

---

## 一、绿名单的完整数学

**生成时**：前一 token $x_{t-1}$ 经哈希 h 把词表分成绿名单 G（一半）与红名单；logits 里绿名单加 δ：

$$P(\text{绿}) = \frac{\sum_{g\in G} e^{z_g + \delta}}{\sum_{all} e^{z_i + \delta \cdot [i in G]}}$$

δ=2 时即使文本要求必须用红词，整体绿占比仍会显著高于 50%（softmax 的软偏置）。

**检测时**：不需要模型——数绿 token 占比。无水印文本绿占比 ~50%（二项分布 N·0.5, √(N·0.25)），z 分数：

$$z = \frac{|\text{绿}| - N/2}{\sqrt{N \cdot 0.25}}$$

N=200、绿占比 62% → z ≈ 3.4（p≈0.0003）；N=500、绿 62% → z≈5.4（几乎断定）。**文本越长检测越容易**——短文本（<100 token）天然功效不足。

**三个变体**：上下文宽度（前一 token vs 前 h 个 token 的哈希——更抗局部改写）；δ 调度（低熵位置如人名后降低 δ，防文本不通顺）；Levenshtein 对齐检测（处理插入删除的 token 位移）。

## 二、攻击面分类与防御

| 攻击 | 手法 | 效果 | 缓解 |
|---|---|---|---|
| **同义改写** | 用另一个 LLM 改写（保意思换 token） | 强——绿占比被稀释 | 语义感知水印 / 句级水印 |
| **翻译** | 中→英→中 | 强 | 翻译不变的水印（研究前沿） |
| **截断拼接** | 人写 + AI 写混合 | 中——只 AI 段带水印 | span 级检测（定位哪些段是 AI） |
| **低温度采样** | 温度→0 逐 token 取最大 | 中——削弱随机性 | 调度式 δ |
| **有意攻击者** | 知道算法后定向避开 | 取决于密钥保密 | 密钥化哈希（未公开密钥） |

**根本张力**：水印强度 δ↑ → 检测性↑ 但质量↓（数学/代码任务上绿名单偏置会排挤正确 token——某研究显示强水印下代码任务掉分明显）。**「质量无损的水印」与「抗强改写的水印」目前不可兼得**——研究在语义感知水印（改写后水印存于语义而非 token 表面）方向推进。

## 三、检测的方法家族与合规版图

**三类检测器**（水印之外）：

1. **训练式分类器**：OpenAI 早期 AI 文本分类器（已因准确率低下线）——对「非母语者的人类文本」误伤严重；
2. **困惑度检测**：AI 文本的困惑度异常低（太流畅）——强模型生成的文本困惑度与人类无法区分（失效中）；
3. **C2PA 内容凭证**：媒体元数据签名（生成时写入「本内容由模型 X 生成」+ 密钥签名）——可剥离但链路可信，图像/视频领域的事实标准（OpenAI/Google/Adobe 联盟）。

**合规版图**：我国《生成式人工智能服务管理暂行办法》+《人工智能生成合成内容标识办法》（显式+隐式标识强制）；EU AI Act 要求 AI 生成内容可检测（技术中立，水印是达标手段之一）；美国行政令要求内容认证标准（NIST 牵头）——**「AI 生成内容必须可标识」已是全球监管共识，水印是主要技术路径之一**。

## 常见误区

- **「水印是不可删除的」** —— 软水印（token 分布偏置）可被**改写攻击**稀释（用另一个 LLM 改写→洗掉水印）；密钥水印（ Kirchenbauer 方案）需知道密钥才能检测，但不知道密钥也可以通过大量查询统计破解。
- **「有水印就能证明是 AI 生成的」** —— 水印是**统计信号**而非确定性证明：z 分数高→高度可能是 AI，但不是法律级的证据——需要与其他证据（元数据/日志）结合。
- **「水印不影响生成质量」** —— 绿名单偏置限制了 token 选择的自由度——在低熵文本（代码/数学公式）中可能显著影响质量；需要自适应 δ（按位置熵调整强度）。
- **「水印只需要在生成端实现」** —— 检测端也需要知道密钥与算法——标准化的检测协议（如 C2PA 的元数据标准）是水印生态的另一半。

## 四、要点总结

1. **绿名单机制**：前一 token 哈希分绿/红，绿名单加权生成；检测=数绿占比算 z。
2. **z 分数**：偏离 50% 的标准化距离；z>4 假阳率 ~10⁻⁴；长文本检测更容易。
3. **δ 的张力**：强水印伤质量（数学/代码尤甚）——1.5~2.5 是工程甜点区。
4. **攻击面**：改写/翻译最强（稀释水印）；密钥化 + 语义感知水印是缓解方向。
5. **定位**：水印是「提高滥用成本的统计信号」而非「绝对防伪」——单独不可定罪。
6. **合规**：全球监管已要求 AI 内容可标识——C2PA（媒体）+ 软水印（文本）是两大技术支柱。
